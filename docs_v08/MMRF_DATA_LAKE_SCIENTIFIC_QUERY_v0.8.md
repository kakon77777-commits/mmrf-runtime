# MMRF v0.8 Data Lake & Scientific Query Plane

## 1. Scope

The v0.8 lake contains only L0 public mathematical data:

- prime values generated by the build process;
- ordinal positions;
- previous-prime gaps;
- bit lengths and decimal digits;
- residues modulo 6, 30 and 210;
- backward-indexed prime-family flags.

It contains no source composite, factor certificate, source–factor relation,
RSA target, factor candidate or narrowing index.

## 2. Columnar shards

The current runtime uses compressed NumPy NPZ columns because PyArrow and
Parquet are not installed in the execution environment.

Each 100,000-integer range is stored as one immutable shard with independent
arrays:

```text
prime
ordinal
bit_length
decimal_digits
previous_gap
residue_6
residue_30
residue_210
family_flags
```

A logical content hash is computed from canonical column order, dtype, shape
and raw array bytes. The CID therefore represents mathematical content rather
than ZIP-container metadata.

## 3. Incremental append

Generation 1 covers `[0, 1,000,000)`.
Generation 2 appends `[1,000,000, 2,000,000)`.

Existing shards are never rewritten. Prime-family pairs are indexed at their
larger observed member so a later append cannot change a prior shard.

## 4. Scientific Query Language

MMRF-SQL 0.8 exposes only aggregate queries:

- dataset metadata;
- interval density;
- prime-gap quantiles;
- prime-gap histogram;
- residue distribution;
- prime-family counts;
- workflow replay.

No exact-prime-list endpoint exists.

## 5. Column pruning

Index-only queries read no NPZ file. Column scans load only the arrays needed
for the requested statistic. Gap queries load `previous_gap`; residue queries
load only the selected residue column.

## 6. Reproducible workflows

A workflow binds:

- workflow document SHA-256;
- current dataset manifest SHA-256;
- each query SHA-256;
- each result SHA-256;
- deterministic scan-profile fields;
- final output SHA-256.

Runtime elapsed milliseconds are deliberately excluded from the reproducible
output hash.

## 7. Integrity sampling

The primary lake can be mirrored as ciphertext-independent public shards.
Sampling verifies:

- transport file SHA-256;
- logical content SHA-256;
- CID;
- column lengths;
- row count;
- monotonic prime ordering.

A corrupted mirror shard is detected without trusting the mirror's database.

## 8. Migration boundary

NPZ is the implemented v0.8 storage profile, not a claim that Parquet is
already available. The manifest and query layers are designed so that a future
Parquet backend can preserve the same CIDs, aggregate semantics and workflow
contracts.
